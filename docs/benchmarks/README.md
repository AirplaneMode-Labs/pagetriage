# Benchmarks: the raw files

Every benchmark figure that this repository quotes, in the [README](../../README.md), in [`docs/`](../) and on the [demo page](https://airplanemode-labs.github.io/pagetriage/),
has its raw output committed here (owner decision, 20 Nov 2026). This page lists every file: what it is, when and at which commit it was made, on which machine,
and the exact command that makes it again.

**Nothing here was measured on an 8 GB laptop unless a file says so.** No file does. Every row and every record carries the words `not measured on 8 GB`, and every
file here was made on one Apple M5 Pro Mac with 48 GiB of RAM (the records and the two Chrome CSV files say so; `speed.csv`, `large-doc.csv` and `streams-native.csv`, written by
scripts that only named the processor, name the model and not the RAM, and were made on the same Mac, the only machine used). The 8 GB Windows laptop without a GPU is the target machine and has not been measured
([docs/release.md](../release.md), row 2): a record made on it carries `--eight-gb "measured on 8 GB: ..."` (see "Adding a file").

## What every file carries

- **Date**: the UTC day of the run, `YYYY-MM-DD`: the `date` column of a CSV file, the `date` field of a record.
- **Commit**: the 12-hex-digit git commit the run started from. `-dirty` means the working tree had uncommitted changes to tracked files when it ran; the run measured the
  committed code of that commit plus whatever the dirty tree held. Every row dated 2026-11-19 or 2026-11-18 says `-dirty` because the Sprint 5 and Sprint 6 changes were not
  committed when they were measured. The `eval-*.json` records of 2026-11-20 were made before this change's own edits were committed (the first few say the commit without `-dirty`, because the tree was still clean): `crates/` and
  `params/` are those of the commit named, and the scripts under `bench/` differ by the changes listed in the CHANGELOG (the recorder itself, a `date` column, a fix to `page_type_synth_eval.py` and to
  `page_size_eval.py`). A run from a clean commit is the cleaner provenance; `bench/record_all.sh` makes it again in one command per group.
- **Machine**: model and RAM only (`Apple M5 Pro (Mac17,8), 48 GiB RAM, Darwin arm64`); no host name, user name or serial number.
- **Command**: the exact command, as run from the repository root. For a record it is the `command` field; for a CSV file it is the `command` column or the reproduce cell below.
- **Output**: a CSV file is what the script wrote. An `eval-*.json` record (`pagetriage-bench-record-1`, written by [`bench/record.py`](../../bench/record.py)) keeps the command's
  standard output and error line for line, its exit code and its wall time, and the versions of Python and of the packages the scripts use. The only edit is that the absolute
  path of the repository and of the home folder are replaced by `<repo>` and `~`.

The five CSV files of Sprints 5 and 6 (`speed.csv`, `large-doc.csv`, `streams-native.csv`, `wasm-streams.csv`, `wasm-structure.csv`) had no `date` column when they were first committed. The
column was added on 20 Nov 2026 and filled with the day each file was written, which the file's modification time and the commit that first added it agree on (2026-11-18 for
`wasm-structure.csv`, commit 1de5ff5; 2026-11-19 for the other four, commit 4f7f9d0). Nothing else in those files was changed, and none of their measurements was repeated. The
scripts that write them now write the column themselves.

## Figures with no raw file

A figure for which no raw output exists is not hidden: the page that quotes it says "raw data not kept" next to it, and `claims.json` lists it as such. The classes:

- **Ad hoc timings and measurements made without a repository script**: the build times and the WebAssembly sizes of the `pdf-inspector` decision (`text_layer.md`), the Phase 0
  WebAssembly sizes, the 60,000-copy mutation run and the large-file timings of `text_layer.md`, the `s/MP` speeds of the binarisers, the cost lines of the detector pages ("quality alone ...
  ms", measured in a cloud container or on a Mac, one run each), the 13,000-page memory ratios and the 13,000-hash search time in the README.
- **Figures about earlier versions of the code**: every "how it got there" paragraph of a detector page (what the first version scored), the Howe figures from before the Canny gradient changed,
  the page-typing table before the quality gate stopped some pages (`page_type.md`).
- **Builds that no longer exist**: the size of the Sprint 6 stream-accounting WebAssembly build (2,435,212 bytes raw, 889,888 gzipped), read from a log that was not committed.
- **Checks made once by a person or a tool that prints no summary**: the blank-page observations on DIBCO pages (`blank_page.md`), the 16 synthetic creases found, the `qpdf` rewrites of the corpus, the
  byte-identical reports of the corpus on native, Python and WebAssembly, the `estamp_qr` and `stamp_paper_header` counts of `fusion.md`, the probes marked "1 seed each" or "3 seeds each", the build-directory
  reproducibility check of the wheel in `docs/RELEASING.md`, and the 22 of 22 real QR codes of `qr.md` (that one is a Rust test, `cargo test`, not a benchmark).
- **CHANGELOG.md** records figures as they were in the sprint it describes. Where the file that backs a figure still exists it is in the index above; otherwise the entry is a dated note, not a claim.

Two sets of numbers are settings, not results, and have no raw file: the targets (for example the Phase 1 target of 1.5 F-measure points) and the limits in `crates/pagetriage-core/params/*.toml`, which `tests/scripts/wasm-api-doc.sh`
and `tests/scripts/streams-doc.sh` compare with the pages that quote them.

## How the rule is enforced

`bash tests/scripts/benchmarks.sh` (part of `tests/scripts/run-all.sh`, so part of CI on Linux, macOS and Windows) runs [`tests/scripts/benchmarks-check.mjs`](../../tests/scripts/benchmarks-check.mjs) on this tree and then on copies of it with one thing broken at a
time, each of which must fail:

- every file here is in the index, and every index row names a file that exists, with the date, commit and machine the file itself carries and a reproduce command that writes it;
- every CSV row and every record carries a date, a commit, a machine and a command, says `not measured on 8 GB` (unless it was made with `--eight-gb`, and then the machine must be an 8 GB one), is under 5 MB, and holds no home or builder path;
- [`claims.json`](claims.json) lists the figures that the README, `docs/` and the demo quote: the text that quotes each (which must still be in its page), and for each number in that text either the row of a file here that it equals (or a value derived from it, such as a range rounded the way the page writes it), or a note that the number is a setting, or the words "raw data not kept" in the same table row or paragraph;
- in the README Benchmarks table, the demo's results table and the "What was measured" table of the write-up, every number in the result and trust cells is inside a claim; and in the README, `bench/README.md`, `docs/` and the demo, any line that quotes a timing, a throughput or a byte count is inside a claim or says "raw data not kept";
- every results section of `docs/detectors/*.md` and `docs/prepare.md` has a `Raw results:` line naming committed files, or saying that none exist;
- the README Benchmarks section and the demo link this folder.

`tests/scripts/wasm-api-doc.sh` and `tests/scripts/streams-doc.sh` also compare the tables of `docs/wasm-api.md` and `docs/detectors/streams.md` with the CSV rows, as before, and now require a date.

## Adding a file

1. Run the script through the recorder: `python -I bench/record.py --out docs/benchmarks/eval-NAME.json -- python -I bench/SCRIPT.py ...` (or give the script a `--csv` option that writes `date`, `machine`, `command` and `commit`
   columns and `eight_gb_laptop`). Add the command to `bench/record_all.sh` and a row to the index above.
2. Add the figures you quote to [`claims.json`](claims.json), with the text that quotes them.
3. For a measurement on the 8 GB target machine: `python -I bench/record.py --out docs/benchmarks/eval-quality-time-8gb.json --eight-gb "measured on 8 GB: <Windows version, CPU, RAM, GPU, Chrome>" -- python -I bench/quality_synth_eval.py --only time`.
   That is the only way a file can say it was measured on an 8 GB laptop; the checker then requires an 8 GB machine in it.
4. `bash tests/scripts/benchmarks.sh`.
